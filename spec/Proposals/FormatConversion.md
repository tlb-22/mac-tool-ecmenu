# 图片 / PDF 格式转换【暂不实现】

本提案不属于当前产品的功能集合、菜单设计或验收范围。

## 菜单与输入

`转换格式` 是一级菜单，其二级目标格式依次为 PNG、JPG、HEIC、WebP、TIFF、GIF、BMP 和 PDF，并根据选择集合省略不可用目标。

支持同一组格式作为输入和输出。`.jpg` 与 `.jpeg` 均属于 JPG 输入，JPG 输出扩展名统一为 `.jpg`。

- 单个受支持文件显示 `转换格式`。
- 多个静态图片可以批量转换。
- 同类型的多个 GIF 或同类型的多个 PDF 可以批量转换。
- 静态图片与容器输入混选、GIF 与 PDF 混选、选择集合中包含文件夹或不支持格式时，不显示该菜单。
- 与所有输入均相同、不会改变任何对象的目标格式不显示。

所有转换遵循 `输入 → 解码为一个或多个图像帧 → 每帧独立编码`。

## 转换规则

### 静态图片

PNG、JPG、HEIC、WebP、TIFF、BMP 之间可以互转，也都可以输出为 GIF 或 PDF。每个输入文件直接产生一个输出文件：

```text
photo.png → photo.jpg
photo.png → photo.gif   # 单帧
photo.png → photo.pdf   # 单页
```

目标格式与输入相同时，该输入跳过，不复制也不重新编码。批量选择含多种格式时，只要至少一个输入需要转换，目标项就可用：

```text
a.png + b.jpg 选择 PNG
→ a.png 跳过
→ b.png 新建
```

每个静态图片独立输出。多图转 PDF 不合并为多页文档，多图转 GIF 不合并为动画。

### GIF 输入

GIF 无论包含一帧还是多帧，都在源文件同级创建独立输出文件夹，并逐帧编号：

```text
loading.gif → PNG

loading/
├── loading-1.png
├── loading-2.png
└── loading-3.png
```

GIF 输入时不显示 GIF 目标项。多个 GIF 各自创建输出文件夹，互不共用。

### PDF 输入

PDF 无论包含一页还是多页，都在源文件同级创建独立输出文件夹，并逐页编号：

```text
document.pdf → PNG

document/
├── document-1.png
├── document-2.png
└── document-3.png
```

PDF 输入时不显示 PDF 目标项。多个 PDF 各自创建输出文件夹，互不共用。

### 输出容器

每个解码后的图像帧只生成一个目标文件：

- GIF 输出是单帧文件，不包含动画、帧率、循环次数或帧延迟配置。
- PDF 输出是单页文件，不进行多页合并。
- GIF 的多帧与 PDF 的多页在输出端保持为多个独立文件。

## 质量

转换以质量优先，保留原始视觉方向和像素尺寸；转换参数固定，用户不可配置。

| 格式 | 固定策略 |
|---|---|
| PDF 输入 | 300 DPI 渲染 |
| PNG | 无损，保留 Alpha，保持像素尺寸 |
| TIFF | 优先无损，尽量保留 Alpha，保持像素尺寸 |
| BMP | 高质量无损；透明度按格式能力处理 |
| JPG | 100% 质量；透明区域合成到白色背景 |
| HEIC | 100% 质量；系统编码器允许时保留 Alpha |
| WebP | 优先 lossless；系统不支持时使用最高质量有损编码，尽量保留 Alpha |

输出应保证视觉方向正确。基础方向信息尽量保留，不承诺完整保留 EXIF、GPS 或 Maker Notes。

## 位置与命名

- 静态图片输出到源文件同级目录。
- GIF 与 PDF 的逐帧、逐页结果输出到同基础名文件夹。
- 文件或输出文件夹第一次冲突时在基础名后追加 `_copy`，后续冲突依次追加 `_copy2`、`_copy3`；`copy` 与数字之间不加空格。
- 已有输出文件夹不复用，已有文件不覆盖。
- 源文件始终保留，不移动、不修改、不删除。

示例：

```text
photo.jpg 已存在  → photo_copy.jpg
document/ 已存在  → document_copy/
```

## 完成与失败

转换不打开输出目录，也不自动选择输出。批量转换允许部分成功，已成功结果保留；其余反馈遵循[统一命令行为](../Requirements/CommandBehavior.md)。
