# 运行机制的独立演进边界

以下能力需要独立的产品边界与验收设计，尚未实施。当前运行约束见[系统架构](../Technical/Architecture/Main.md)。

| 方向 | 当前能力边界 | 实施前需要明确 |
|---|---|---|
| 配置有限时间收敛 | 分布式通知提示失效，Extension 通过已认证查询更新副本；通知无可靠到达承诺 | 收敛时限、主动刷新触发条件、失败重试与后台成本 |
| 命令回执或持久队列 | 写出成功与业务完成分离，当前协议没有业务完成回执 | 已接受/已完成/未知的状态、重复执行与幂等边界、宿主退出后的恢复语义 |
| 全局并发限制 | Router 独立持有各次命令任务，进度与用户取消按请求区分 | 等待队列、资源公平性、取消与部分成功的产品行为 |
| 独立 Swift module 或替换 IPC 技术 | 目录与窄调用边界表达责任，保留现有 targets 和已认证本地 socket | 真实依赖的编译约束、签名与部署要求、迁移和性能证据 |
| 存储 schema 演进 | 已发布偏好键、模板格式与独立迁移保持一致 | 新数据需求、迁移失败与恢复策略，以及升级验收 |
| 错误窗口交互调整 | 能力反馈策略复用当前原生警告和进度窗口 | 是否改变模态行为、焦点与 Space 语义，以及真实窗口验收 |

[撤销与重做](CommandUndo.md)有独立提案，历史与恢复资源的所有权及适用命令在该处维护。
